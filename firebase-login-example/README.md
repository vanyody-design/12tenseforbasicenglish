# ตัวอย่างระบบ Login ด้วย Firebase (Email + Password)

ตัวอย่างแยกอิสระ **ไม่เกี่ยวกับโปรแกรม Tense Lab** ในโฟลเดอร์แม่ — Tense Lab ยังเปิดจาก `index.html` ได้ตรง ๆ เหมือนเดิม ไม่มี dependency ภายนอก

## มีอะไรบ้าง

- สมัครสมาชิกด้วยอีเมล + รหัสผ่าน พร้อมตั้งชื่อที่ใช้แสดง
- เข้าสู่ระบบ / ออกจากระบบ
- ส่งอีเมลยืนยันตัวตนอัตโนมัติตอนสมัคร และส่งซ้ำได้
- ลืมรหัสผ่าน → ส่งลิงก์ตั้งรหัสใหม่ทางอีเมล
- ตัวเลือก "จำฉันไว้" (localStorage) กับไม่จำ (sessionStorage)
- แปลรหัสข้อผิดพลาดของ Firebase เป็นภาษาไทยทุกกรณีที่เจอบ่อย
- ธีมมินิมอลเข้าชุดกับ Tense Lab รองรับโหมดมืดตามระบบ

## ไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `firebase-config.js` | **ไฟล์เดียวที่ต้องแก้** — ใส่ค่าโปรเจกต์ Firebase ของคุณ |
| `auth.js` | ตรรกะทั้งหมด: สมัคร เข้าระบบ ออก รีเซ็ตรหัส เฝ้าสถานะล็อกอิน |
| `index.html` | หน้าเว็บและสไตล์ |

---

## ตั้งค่า 4 ขั้น

### 1. สร้างโปรเจกต์

เข้า [console.firebase.google.com](https://console.firebase.google.com) → **Add project** → ตั้งชื่อ → สร้างให้เสร็จ

### 2. เปิดใช้ Email/Password

ในโปรเจกต์ → **Build → Authentication** → **Get started** → แท็บ **Sign-in method** → เลือก **Email/Password** → เปิดสวิตช์ **Enable** → **Save**

> ถ้าข้ามขั้นนี้ จะเจอข้อผิดพลาด `auth/operation-not-allowed`

### 3. เอาค่า config มาใส่

**Project settings ⚙** → แท็บ **General** → เลื่อนลงหา **Your apps** → กดไอคอน `</>` (Web) → ตั้งชื่อเล่นแอป → **Register app**

จะได้ออบเจกต์ `firebaseConfig` มา เอามาแทนค่าใน `firebase-config.js`:

```js
export const firebaseConfig = {
  apiKey: 'AIza...',
  authDomain: 'my-project.firebaseapp.com',
  projectId: 'my-project',
  storageBucket: 'my-project.firebasestorage.app',
  messagingSenderId: '123456789012',
  appId: '1:123456789012:web:abc123'
};
```

### 4. เปิดผ่าน server

```bash
npx serve .
```

แล้วเปิดลิงก์ที่ขึ้นมา (เช่น `http://localhost:3000`)

> **เปิดด้วยการดับเบิลคลิกไฟล์ไม่ได้** เพราะไฟล์นี้ใช้ ES Module (`<script type="module">`) ซึ่งเบราว์เซอร์บล็อกบน `file://` ทั้งหมด ต่างจาก Tense Lab ที่ใช้ script ธรรมดาจึงเปิดตรง ๆ ได้

เวลาขึ้นจริงบนโดเมนของคุณเอง ต้องไปเพิ่มโดเมนนั้นที่ **Authentication → Settings → Authorized domains** ด้วย (localhost เปิดให้อยู่แล้ว)

## เรื่องที่คนเข้าใจผิดบ่อย

**`apiKey` เปิดเผยในโค้ดฝั่งหน้าเว็บได้ ไม่ใช่ความลับ**

Firebase ออกแบบมาให้ค่าพวกนี้อยู่ในโค้ดที่ใครก็เปิดดูได้ มันทำหน้าที่แค่ระบุว่า "นี่คือโปรเจกต์ไหน" ไม่ใช่กุญแจให้สิทธิ์เข้าถึงข้อมูล ความปลอดภัยจริงมาจากสามอย่างนี้แทน:

| กลไก | ป้องกันอะไร |
|---|---|
| **Security Rules** ของ Firestore / Storage | กันไม่ให้คนอ่านหรือเขียนข้อมูลที่ไม่ใช่ของตัวเอง — สำคัญที่สุด |
| **Authorized domains** | กันไม่ให้เว็บอื่นเอา config ของคุณไปใช้ล็อกอิน |
| **การตรวจสอบฝั่งเซิร์ฟเวอร์** | ตรวจ ID token ก่อนให้ข้อมูลสำคัญ |

ดังนั้นถ้าจะเก็บข้อมูลผู้ใช้จริง **ต้องเขียน Security Rules เสมอ** อย่าปล่อยเป็นโหมดทดสอบที่เปิดให้ทุกคนอ่านเขียนได้

**รหัสผ่านไม่เคยถูกเก็บในโค้ดหรือฐานข้อมูลของคุณ** — Firebase จัดการแฮชและเก็บเองทั้งหมด โค้ดฝั่งหน้าเว็บแค่ส่งไปให้แล้วรับผลลัพธ์กลับมา

## ถ้าจะเอาไปต่อกับ Tense Lab จริง

ปัจจุบัน Tense Lab เก็บความคืบหน้าไว้ใน `localStorage` ของแต่ละเครื่อง ถ้าอยากให้ล็อกอินแล้วข้อมูลตามไปทุกเครื่อง ต้องทำเพิ่มดังนี้:

1. เพิ่ม **Firestore** เก็บ state ของผู้เรียนไว้ที่ path `users/{uid}`
2. ใน `app.js` เปลี่ยน `save()` / `load()` ให้เขียนอ่านผ่าน Firestore แทน `localStorage` เมื่อล็อกอินอยู่ (ยังใช้ `localStorage` เป็นตัวสำรองตอนออฟไลน์ได้)
3. เขียน Security Rule ให้แต่ละคนแตะได้แค่ข้อมูลตัวเอง:

```js
match /users/{uid} {
  allow read, write: if request.auth != null && request.auth.uid == uid;
}
```

4. ย้าย Tense Lab ไปรันบน server ด้วย เพราะจะต้องใช้ ES Module เหมือนกัน

แลกมาด้วยการที่โปรแกรมจะเปิดแบบดับเบิลคลิกไม่ได้อีกต่อไป และต้องต่อเน็ตตลอด — ควรชั่งดูก่อนว่าคุ้มไหมกับกลุ่มผู้ใช้จริง
